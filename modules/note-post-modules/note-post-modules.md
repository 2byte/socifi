## Post type module

Интерактивные посты построенные на компонентной системе vue3. Каждый пост может быть отдельным модулем, который можно подключать к заметкам. Модуль может содержать различные типы контента, такие как текст, изображения, видео и интерактивные элементы.

- Пост модуль может создавать локальные сервера с открытием внешнего доступа. Сервера могут быть как http, так и websocket. Это позволяет создавать интерактивные приложения внутри постов, которые могут взаимодействовать с пользователем в реальном времени. Из диапазон портов, выделенные для постов открывается свободный порт и закрепляется за постом.
  Для локального сервера возможно открытие внешнего доступа вида /api/post/:post_id/internal/:id где :post_id - id поста, :id - id внутреннего сервера поста или slug

- Пост модуль может иметь хранилище данных, которое позволяет сохранять состояние и данные между сессиями. Это может быть полезно для создания сложных интерактивных приложений, которые требуют сохранения пользовательских данных.

- Также пост модуль может содержать собственные стили и скрипты, которые будут применяться только к этому модулю. Это позволяет создавать уникальные визуальные эффекты и функциональность для каждого поста.

# Технические детали

Поле `content` в таблице `notes_posts` хранит json объект, который описывает структуру поста. Этот объект может содержать различные типы контента, такие как текст, изображения, видео и интерактивные элементы. Каждый элемент контента может иметь свои собственные свойства и методы, которые определяют его поведение и внешний вид.

**С версии с форматами** у поста есть текст (`content`, формат `format`: `markdown` по умолчанию или `text`) и необязательный прикреплённый модуль в колонке `module_slug`. Пост может быть только текстом, только модулем или текстом с модулем под ним. Раньше модуль хранился в самом `content` как `{ "type": "module", ... }`; миграция `0004` перенесла такие посты в `module_slug`, оставив текст пустым.

`content`.`props` - объект, который содержит свойства модуля поста. Эти свойства могут быть использованы для настройки поведения и внешнего вида модуля.

```json
{
  "type": "module",
  "props": {
    "id": "my-post-module",
    "description": "This is a description of my post module.",
    "author": "2byte",
    "version": "1.0.0",
    "dependencies": {
      "vue": "^3.0.0"
    },
    "servers": [
      {
        "enabled": true,
        "type": "http",
        "port": "auto",
        "external_access": true
      },
      {
        "enabled": true,
        "type": "websocket",
        "port": "auto",
        "external_access": true
      },
      {
        "enabled": false,
        "type": "tcp",
        "port": "auto",
        "external_access": false
      }
    ]
  },
}
```

# Как это работает сейчас

- **Загрузка.** Бэкенд при старте сканирует папки модулей, ищет `Ntpm*Module.ts` и монтирует маршруты модуля (`NtpmServiceManager`). Фронт подгружает `pages/ntpm-main.vue` модуля по slug (`ntpm-<slug>/`) и монтирует его в заметке (`NtpmModuleHost.vue`).
- **Пост.** Модуль выбирается при создании поста и хранится в `notes_posts.module_slug` (`moduleSlug` в API); текст поста лежит в `content`.
- **Адреса.** Снаружи `/api/post/:post_id/internal/:slug/...`; префикс `/api` срезается прокси, поэтому на бэкенде маршруты начинаются с `/post/...`.
- **Доступ.** `Authorization: Bearer <токен>`: либо NTPM-токен поста (`ntpm_…`, `/ntpm/posts/:post_id/token`), либо access-токен владельца. Запись принадлежит модулю и посту, чужие записи недоступны. UI модуля работает с NTPM-токеном поста, а не с сессией пользователя.
- **Страница модуля** получает props `{ postId, token, apiRoot }`. В страницах нельзя импортировать значения из серверного класса модуля (он тянет SQLite) — общие типы и хелперы выносятся в `*.shared.ts`.
- **Пример:** `ntpm-checklist/`.
- **Пока не реализовано:** отдельные серверы на портах (`servers` в `props`), собственные стили и скрипты модуля вне его страницы.

# Гости (доступ по публичной ссылке)

Владелец может расшарить заметку или пост по ссылке (`/#/s/<token>`). Человек с такой ссылкой — **гость**: у него нет сессии, а модуль в расшаренном посте он видит только если модуль к этому готов.

- **Модуль закрыт для гостей по умолчанию.** Без объявления `guests` в конфиге гость видит вместо модуля заглушку, а любой запрос к модулю с гостевым токеном получает `403`. Так модуль, который про гостей не знает (например, `data-vault` с cookies и паролями), не открывается случайно.
- **Объявление.** В конфиге модуля: `guests: { read: true, write: true }`.
  - `read` — гость видит модуль, получает записи и статистику, слушает WebSocket.
  - `write` — модуль *умеет* принимать изменения от гостей (создание, изменение, удаление, сообщения в WS).
- **Решение владельца.** Запись гостям включается отдельно для каждого поста в его системном поле `props`: `{ "guests": { "write": true } }` (переключатель «Guests can change this module's data» в диалоге шаринга). Итог: гость может писать, только если `guests.write` объявлен в модуле **и** включён в `props` поста. Чтение отдельного переключателя не требует: владелец уже решил поделиться.
- **Как гость ходит в модуль.** Токен — `share:<share token>` в `Authorization: Bearer` (для WS — в `?token=`). Он привязан к ссылке, поэтому выключение ссылки сразу закрывает доступ. Ссылка на пост даёт доступ только к этому посту, ссылка на заметку — к постам заметки.
- **Что делает базовый класс.** Все базовые маршруты (`/entries`, `/stats`) и WS уже проверяют права через `NtpmBaseModule.deny(auth, "read" | "write", set)`.
  - **Свои маршруты:** после `verifyNtpmAuth` вызывайте `const denied = mod.deny(auth, "read", set); if (denied) return denied;` (для изменяющих — `"write"`).
  - **WS-каналы:** в `ctx.role` приходит `"owner"` или `"guest"`. Гость не может отправлять сообщения в каналы, если запись ему не разрешена.
- **UI.** Для гостя хост запускает страницу модуля с токеном ссылки и добавляет props `role: "guest"` и `readonly: boolean`. Страница должна уметь показать режим «только просмотр» (скрыть формы и кнопки изменения). Владельцу эти props не передаются. Пример — `ntpm-checklist/pages/ntpm-main.vue`.
- **Чего не делать.** Не отдавайте гостю то, что владелец не хотел бы показывать публично: `props` поста, токены, чужие данные других постов. Запись в модуль гостем — это запись от анонимного посетителя, валидируйте ввод как для внешнего.
